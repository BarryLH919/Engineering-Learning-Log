# Git 出错处理的 6 个标准步骤

遇到 Git 报错时，保持冷静并遵循以下 6 个标准步骤，可以最大程度避免数据丢失并安全恢复仓库状态：

## 1. 停止连续操作（防止二次破坏）

遇到报错时，切忌连续尝试不熟悉的命令（尤其是带 `--force` 或 `--hard` 的指令）。保持当前工作区原状是挽救数据的第一步。

## 2. 检查当前仓库状态（摸清现状）

运行以下命令查看当前所处的分支、是否有未提交的修改，以及是否处于合并冲突（Merge Conflict）或游离 HEAD（Detached HEAD）等特殊状态：

```bash
git status
```

## 3. 查阅操作历史与差异（定位问题源头）

* **查看本地所有 HEAD 移动记录**（找回误删提交或回退版本的“后悔药”）：
  ```bash
  git reflog
  ```
* **查看最近的提交历史**：
  ```bash
  git log --oneline -n 10
  ```
* **检查具体的文件改动**：
  ```bash
  git diff
  ```

## 4. 创建临时备份（确保数据安全）

在进行任何回滚或重置操作前，先创建一个临时分支，或者直接将整个项目文件夹复制到其他位置。这样即使后续修复出错，也能随时回到备份点：

```bash
git branch backup-temp
```

## 5. 选择对应的恢复策略（精准修复）

根据具体报错场景，选择最安全的修复命令：

* **撤销工作区未暂存的修改：**
  ```bash
  git checkout -- <文件名>
  # 或
  git restore <文件名>
  ```
* **取消已暂存（add）的文件：**
  ```bash
  git reset HEAD <文件名>
  # 或
  git restore --staged <文件名>
  ```
* **修改刚提交的 Commit 信息或漏掉的文件：**
  ```bash
  git commit --amend
  ```
* **撤销已推送到远程的错误提交：**
  优先使用反向提交，避免直接用 `git reset --hard` 破坏团队成员的历史记录：
  ```bash
  git revert <commit-id>
  ```
* **解决代码合并冲突：**
  手动编辑包含 `<<<<<<<` 标记的文件，保留正确代码后执行：
  ```bash
  git add <文件名>
  git commit
  ```

## 6. 验证状态并清理备份（收尾确认）

再次运行状态与历史命令，确认分支干净、代码完整且能正常运行：

```bash
git status
git log --oneline -n 5
```

确认无误后，删除第 4 步创建的临时备份分支：

```bash
git branch -d backup-temp
```
